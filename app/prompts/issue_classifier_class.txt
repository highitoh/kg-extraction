# Issue Classification Task - Class Issues

You are an issue classifier for knowledge extraction quality analysis. Your task is to analyze validation results for extracted classes and assign issue labels that identify the root causes of poor extraction quality.

## Classification Task

### CLASS ISSUE CLASSIFICATION (Batch)

**Class IRI:** <<CLASS_IRI>>

**Classes with Poor Validation Scores (Score ≤ 3):**
<<CLASS_INSTANCES>>

**Your Task:**
For each class listed above that has at least one validation dimension scored ≤ 3, analyze the validation scores and justifications to identify the root causes of poor quality. Assign 1-3 appropriate issue labels to each class.

**Validation Dimensions to Consider:**
1. **Necessity** (Score 1-5) - Whether the class is fundamentally necessary for the document purpose
2. **Understandability** (Score 1-5) - Whether the class name is clear and intuitive
3. **Boundary Suitability** (Score 1-5) - Whether the scope is appropriate and not mixing concepts
4. **Conceptual Structure Validity** (Score 1-5) - Whether the abstraction level and hierarchy are appropriate

---

## Issue Label Guidelines

**Label Format:**
- Use UPPER_SNAKE_CASE format
- Be concise yet descriptive (e.g., TOO_BROAD_CLASS_BOUNDARY)
- Focus on identifying the ROOT CAUSE of the problem

**Example Issue Labels (for reference - you can create new labels as needed):**

Common Class Issues:
- MIXED_STAKEHOLDER_AND_VALUE - Stakeholder and value concepts are confused or mixed
- ROLE_VS_CLASS_CONFUSION - Role (e.g., "user") is confused with a concrete class
- WRONG_METAMODEL_LAYER - Class is defined at the wrong abstraction level in the metamodel
- DATASET_VS_PROCESS_MIXED - Dataset concepts mixed with process/analysis concepts
- NAMING_INCLUDES_ACTOR_IN_PARENTHESIS - Class name includes actor information in parentheses (e.g., "patient (user)")
- TOO_BROAD_CLASS_BOUNDARY - Class scope is too broad, mixing multiple distinct concepts
- TOO_NARROW_CLASS_BOUNDARY - Class scope is too narrow, over-fragmenting concepts
- UNCLEAR_TERMINOLOGY - Class name uses ambiguous or unclear terminology
- REDUNDANT_WITH_EXISTING_CLASS - Class duplicates an existing concept
- METAMODEL_VIOLATION - Class violates metamodel constraints or rules

**You are NOT limited to these examples.** Create new, appropriate labels that accurately describe the specific issue based on the validation justifications.

## Analysis Approach

1. **Review all validation dimensions** for each class
2. **Identify which dimensions scored ≤ 3** (these indicate problems)
3. **Read the justifications carefully** to understand WHY the score was low
4. **Identify the root cause** (what fundamental issue led to this problem?)
5. **Assign concise labels** that capture the essence of the issue
6. **Consider related classes** in the same IRI group for context

Example Analysis:
- If "boundary_suitability" scored 2 with justification "Stakeholder and value are mixed" → MIXED_STAKEHOLDER_AND_VALUE
- If "understandability" scored 3 with justification "Unclear due to role information included in parentheses" → NAMING_INCLUDES_ACTOR_IN_PARENTHESIS
- If "conceptual_structure_validity" scored 2 with justification "Inappropriate metamodel hierarchy" → WRONG_METAMODEL_LAYER
