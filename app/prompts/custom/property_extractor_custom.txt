Property Extraction Rules (Concise)

Goal
- Extract high-recall candidates while keeping precision via explicit evidence, provenance, and confidence flags.

1) Relation preconditions
- Propose inter-class properties only when an explicit connector exists:
  - requires, depends on, implements, realizes, provides, produces, exposes, receives, allocated to, by/through/via.
- If only co-occurrence/listing exists, do not emit strong relation; emit speculative=true or NO_RELATION.

2) Sentence scope
- Prefer same-sentence extraction.
- Cross-sentence extraction requires clear coreference/discourse linkage; otherwise speculative=true.

3) Directionality
- Keep subject->object direction for active voice.
- For passive voice ("is implemented by", "is realized by"), add flipped candidate and mark lower-confidence unless strongly supported.

4) Requirement vs Value disambiguation
- Requirement candidates (hasBusinessRequirement/hasSystemRequirement) need explicit obligation/modal cues:
  - must, shall, required to, needs to.
- Outcome/benefit language without obligation defaults to hasValue.
- If both outcome and obligation exist in one clause, allow dual candidates (Value + Requirement).

5) Priority verbs and mandatory proposal
- Always propose candidates (with provenance) when explicit verbs appear:
  - implements, realizes, exposes, produces, sends, receives, uses, provides, consumes.
- If evidence is weak, keep candidate but set speculative=true and lower rank.

6) Relation-specific guards
- participates: require explicit role-involvement wording (participates/involved in/takes part).
- receivesValue: require explicit recipient/beneficiary phrasing.
- producesOperationalData/interfaceProducesOperationalData:
  - require system/interface-like subject and data-like object.
- exposedBy/exposesInterface:
  - require API/interface/endpoint-like object.

7) Destination quality
- Short generic destinations (e.g., data, model, result) => REVIEW unless strongly qualified.
- Do not invent destination when evidence is weak.

8) Provenance
- Attach cue token(s) and source span to each candidate.
- Carry speculative=true as first-class metadata to downstream reviewer/ranker.

9) Ranking preference
- Prefer candidates with:
  - explicit connector,
  - correct syntax mapping,
  - concrete destination,
  - non-speculative modality.
