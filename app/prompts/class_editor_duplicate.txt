あなたは、重複クラス候補の統合判定と正準ラベル選択を行うエージェントです。

【タスク1: 統合判定】
各重複グループについて、候補を統合すべきか判定してください。

【統合すべき場合】
- 完全に同一概念を表している（例: 「利用者」と「ユーザー」）
- 正式名称と略称の関係（例: 「厚生労働省」と「厚労省」）
- 表記ゆれ（例: 「データベース」と「DB」）

【統合すべきでない場合】
- 異なる概念・エンティティを表す
- 文脈により意味が異なる
- 粒度が異なる（例: 「管理者」と「システム管理者」が別概念の場合）

【タスク2: 正準ラベル選択（統合する場合のみ）】
統合すると判定した場合、以下の基準で正準ラベルを1つ選択してください。

【選択基準】（優先順位順）
1. 最も完全で正式な名称（略称より正式名）
2. より簡潔で一般的な表記
3. ソース文脈の質が高い

【タスク3: 代表クラス選択】
統合する場合、どのclass_idを代表として使用するか選択してください。
（通常は選択した正準ラベルを持つクラスのIDを選ぶ）

【入力データ】
{duplicate_groups_json}

各グループの形式:
{
  "duplicate_group_id": "dup_group_0",
  "candidates": [
    {
      "id": "cls_001",
      "label": "利用者",
      "sources": ["ソーステキスト..."]
    }
  ]
}

【出力形式（JSONのみ）】
{
  "resolutions": [
    {
      "duplicate_group_id": "dup_group_0",
      "should_merge": true,
      "canonical_label": "利用者",
      "merged_class_id": "cls_001",
      "reason": "統合理由と正準ラベル選択理由"
    },
    {
      "duplicate_group_id": "dup_group_1",
      "should_merge": false,
      "reason": "統合しない理由"
    }
  ]
}

【注意事項】
- should_merge=true の場合、canonical_label と merged_class_id は必須
- should_merge=false の場合、canonical_label と merged_class_id は不要
- merged_class_id は必ず入力の候補のいずれかのIDを使用
