各【プロパティ候補】について、以下の2つを評価してください：

1. 【禁止ルール】への該当有無を3段階で判定
2. 現在の強度(strength)評価が正しいか検証し、再評価

## タスク1: 禁止ルールへの該当判定

【判定カテゴリ】
- ACCEPT: 禁止ルールに該当せず、明確に受け入れ可能
- REVIEW: 禁止ルールへの該当が曖昧で、追加のLLM分析が必要、または強度評価が正しくない
- REJECT: 禁止ルールに明確に該当し、除外すべき

【禁止ルール】
{PROHIBIT_RULES}

## タスク2: 強度評価の検証と再評価

各候補には、PropertyRankerによって評価された強度(strength)と評価根拠(justification)が含まれています。
この強度評価が正しいか検証し、あなたの評価(evaluated_strength)を提供してください。

【強度評価基準】
- 3 / Strong（必須依存）: BがなければAが成立しない
  例: 「認証システム」と「ユーザーデータベース」
- 2 / Medium（機能的依存）: AがBを利用すると効率・性能が上がる
  例: 「検索機能」と「インデックス」
- 1 / Weak（環境的依存）: Bがあると望ましいが、なくても代替手段がある
  例: 「システム」と「監視ツール」
- 0 / None（関連なし）: 論理的に独立している、または関係性が誤っている
  例: 明らかに誤った関係性

## 出力形式（JSONのみ）

{
  "relations": [
    {
      "src_id": "...",
      "dest_id": "...",
      "judgment": "ACCEPT|REVIEW|REJECT",
      "evaluated_strength": 0-3,
      "justification": "禁止ルール評価と強度評価の両方を含む統合的な理由"
    }
  ]
}

【重要な判定ルール】
- 禁止ルールに該当する場合は、必ずjudgment="REJECT"
- 強度評価が元のstrengthと異なる場合は、judgment="REVIEW"にする
- REJECT判定の場合、evaluated_strengthは必ず0にする
- 出力は、入力と同じ順序・同じ要素数のrelationオブジェクト配列
