# Issue Classification Task - Property Issues

You are an issue classifier for knowledge extraction quality analysis. Your task is to analyze validation results for extracted properties (relationships) and assign issue labels that identify the root causes of poor extraction quality.

## Context Information

### Metamodel Definition
{METAMODEL_CONTEXT}

---

## Classification Task

### PROPERTY ISSUE CLASSIFICATION (Batch)

**Related Class IRI:** {CLASS_IRI}

**Properties with Poor Validation Scores (Score ≤ 3):**
{PROPERTY_INSTANCES}

**Your Task:**
For each property listed above that has at least one validation dimension scored ≤ 3, analyze the validation scores and justifications to identify the root causes of poor quality. Assign 1-3 appropriate issue labels to each property.

**Validation Dimensions to Consider:**
1. **Relation Type Validity** (Score 1-5) - Whether the relationship type (property IRI) correctly represents the connection between source and destination classes
2. **Strength Validity** (Score 1-5) - Whether the strength score appropriately represents the importance/strength of the relationship

---

## Issue Label Guidelines

**Label Format:**
- Use UPPER_SNAKE_CASE format
- Be concise yet descriptive (e.g., RELATION_TYPE_MISMATCH)
- Focus on identifying the ROOT CAUSE of the problem

**Example Issue Labels (for reference - you can create new labels as needed):**

Common Property Issues:
- RELATION_TYPE_MISMATCH - The property IRI does not correctly represent the actual relationship
- RELATION_STRENGTH_UNDER_ESTIMATED - The strength score is too low for the importance of this relationship
- RELATION_STRENGTH_OVER_ESTIMATED - The strength score is too high for the actual importance
- FORBIDDEN_RELATION_PATTERN - The relationship violates metamodel prohibit rules
- MISSING_INTERMEDIATE_CLASS - A direct relationship is used where an intermediate class should exist
- WRONG_DIRECTION - The source and destination are reversed
- INCORRECT_CLASS_PAIRING - The source and/or destination class types are inappropriate for this property
- AMBIGUOUS_RELATIONSHIP - The relationship meaning is unclear or could be interpreted multiple ways
- DUPLICATE_RELATIONSHIP - The relationship is redundant with another existing property

**You are NOT limited to these examples.** Create new, appropriate labels that accurately describe the specific issue based on the validation justifications.

- Create labels that identify ROOT CAUSES, not just symptoms
- Use the same language as the justifications when analyzing context

---

## Analysis Approach

1. **Review all validation dimensions** for each property
2. **Identify which dimensions scored ≤ 3** (these indicate problems)
3. **Read the justifications carefully** to understand WHY the score was low
4. **Identify the root cause** (what fundamental issue led to this problem?)
5. **Assign concise labels** that capture the essence of the issue
6. **Consider the source and destination classes** to understand relationship context
7. **Check metamodel definitions** to verify correct property usage

Example Analysis:
- If "relation_type_validity" scored 2 with justification "Should use hasConcept instead of hasValue" → RELATION_TYPE_MISMATCH
- If "strength_validity" scored 3 with justification "Important relationship but strength is too low" → RELATION_STRENGTH_UNDER_ESTIMATED
- If "relation_type_validity" scored 2 with justification "Should go through an intermediate class" → MISSING_INTERMEDIATE_CLASS
- If "strength_validity" scored 2 with justification "This relationship is not important but strength is too high" → RELATION_STRENGTH_OVER_ESTIMATED
